Abstract

Professional web-application testing means juggling a dozen disconnected tools and hand-stitching their output into a report. ReconToReport unifies that workflow.

A single Python orchestrator drives five phases — reconnaissance, traffic capture, automated scanning, targeted exploitation, and harvesting — writing every discovered asset, transaction, and finding into one shared data model. A browser dashboard runs scans and a Jinja templating layer renders a severity-ranked report with CVSS, impact, and remediation per finding. Every active phase is blocked behind an explicit authorization gate.

Phases declare dependencies, so selecting one automatically runs its prerequisites. A failure in any phase is isolated — the run continues.

Method & design

  • Shared data model — targets, assets, transactions, findings, evidence, secrets, auth contexts, reports.
  • Normalization — each tool's output is parsed into one schema, so phases build on each other.
  • Authorization gate — active phases refuse to run without explicit consent.
  • Bounded execution — per-tool time budgets prevent runaway scans.

Contribution & future work

ReconToReport lowers the barrier between a target and a professional assessment: the operator supplies a URL and authorization; the system handles discovery, testing, correlation, and reporting. The shared data model makes findings from different tools comparable and the whole run reproducible. Next: active parameter fuzzing for deeper injection coverage, out-of-band (interactsh) confirmation, host liveness filtering before scanning, and exportable PDF/CSV reports.
