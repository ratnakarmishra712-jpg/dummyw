SECURE//IR-LINK

Secure Line-of-Sight Device-to-Device
Communication over Infrared Light

A wireless-free optical link between two ESP32 nodes using IR LEDs and photodiodes, with the channel secured by an RSA-authenticated Diffie–Hellman key exchange.
PROJECT Secure IR LoS Link

Abstract

Radio links are easy to intercept and jam. This project builds a point-to-point channel out of light instead of radio.

Two ESP32 nodes communicate over a direct infrared beam — an IR LED transmits, a photodiode receives — so data only travels along an unobstructed line of sight. On top of this physical channel, the two nodes negotiate a shared secret and encrypt every message, giving confidentiality even if the beam were observed.

Why infrared / line-of-sight?

  • Hard to intercept — no omnidirectional RF; an attacker must physically sit in the beam.
  • No spectrum / licensing — uses visible-adjacent IR, not congested radio bands.
  • Contained — signal stops at walls and obstacles, naturally limiting range of exposure.

TX path: GPIO 17 → 330Ω → IR LED  ·  RX path: IR photodiode → BC547 (amplify) → GPIO 16 → ESP32

The transmitter modulates the IR LED; the photodiode converts received light to a signal the BC547 amplifies into a clean logic level the receiving ESP32 decodes. A potentiometer tunes the receiver's sensitivity threshold.

Security — handshake & encryption

1
Identity / key setup. Each node holds an RSA key pair; public keys are exchanged and used to authenticate the peer (defeating a man-in-the-beam impostor).
2
Diffie–Hellman exchange. Both nodes send DH public values; each derives the same shared secret, which is never transmitted.
3
Session key. The shared secret becomes a symmetric session key for this conversation.
4
Encrypted messaging. Every payload is encrypted with the session key before it is modulated onto the IR beam, and decrypted on the far side.

RSA authenticates the parties and protects the exchange; Diffie–Hellman establishes a fresh shared key so a captured transcript cannot be trivially replayed or read.

Threat model

  • Eavesdropper — even if light is captured, payloads are encrypted under a key never sent in clear.
  • Impostor node — RSA authentication rejects a peer without the expected key.
  • RF attacker — irrelevant: there is no radio surface to attack.

Future work

  • Higher symbol rate / modulation for greater throughput
  • Forward error correction against ambient-light noise
  • Per-message nonces & authenticated encryption (AEAD)
  • Longer range with focusing optics
