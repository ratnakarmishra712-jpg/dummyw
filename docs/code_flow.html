Call Flow — what runs when you enter a URL

r2r run --url <site> --phases all --i-have-authorization (CLI path; web UI noted at step 1)
Each step = file · function(). Tags: entrycore phasetool storeoutput
1
recontoreport/cli.py
run() entry
Click parses your flags. If --url only → Config.from_url(); if --config → Config.load() (config.py). normalize_url() adds http:// if missing and seeds the scope.
Web UI equivalent: web/app.py scan() → _run_scan() → _build_config() (same Config object).
2
recontoreport/orchestrator.py & phases/__init__.py
parse_phase_arg() → resolve_phases() core
parse_phase_arg("all") → [1,2,3,4,5]. resolve_phases() expands dependencies (e.g. [4] → [1,3,4]) by reading each phase class's depends_on.
3
recontoreport/orchestrator.py
Orchestrator.__init__() → run() core
__init__ builds the DB engine + session factory (db.py), creates tables. run() calls _get_or_create_target() → inserts the targets row and sets status running.
writes → targets
4
recontoreport/orchestrator.py
loop in run() → _run_phase_with_retries() core
For each phase number: build a PhaseContext (config, target_id, session_factory, logger). Authorization gate: if the phase is active and you didn't pass authorization → skip. Otherwise call phase.run() inside try/except so one failure can't kill the run.
5
recontoreport/phases/phase1_recon.py
ReconPhase.run() phase 1 · recon
Calls three sub-steps:
_run_subfinder() → tools/runner.py run() — enumerates subdomains of _registrable_domain(), _parse_subfinder_line() → _store_asset().
_run_crawler() → tools/crawler.py crawl() + parse_html() — BFS fetches pages; each page stored as a transaction, each link/form/param as an asset.
_run_ffuf() → tools/runner.py run() — optional wordlist brute-force; sensitive hits also create a finding.
writes → assets · http_transactions · findings
6
phase2_traffic.py · phase3_scan.py · phase4_exploit.py · phase5_harvest.py
each Phase.run() phases 2–5
P2 TrafficPhase.run() → tools/mitm_addon.py + capture.py, Playwright — logs traffic + captures logins. → http_transactions · auth_contexts
P3 ScanPhase.run() → _run_nuclei() / _run_xss_canary() / _run_privesc_diff() — reads assets + auth_contexts + transactions. → findings
P4 ExploitPhase.run() → tools/jwt_analysis.py, sqlmap — reads transactions + param assets. → findings
P5 HarvestPhase.run() → tools/secrets.py scan_text() — reads transactions (offline). → secret_matches
7
recontoreport/tools/runner.py (every external tool goes through here)
run() / ensure_available() tool
Single safe subprocess wrapper: no shell, captures stdout/stderr, enforces a timeout. subfinder, ffuf, nuclei, sqlmap, mitmdump all launch here. Phase code then parses the output and normalizes it.
8
recontoreport/models.py + db.py (SQLite via SQLAlchemy)
session_scope() → ORM writes/reads shared store
Every phase reads and writes the 8 tables through session_scope(). This is where tools "meet": P1 writes a page body, P5 later reads it; P2 writes two identities, P3 replays and diffs them.
9
recontoreport/orchestrator.py → cli.py / web/app.py
back in run() → status set, results returned core
Target status set to completed/failed; a list of PhaseResult is returned and printed as the phase table.
10
recontoreport/report/generator.py + templates/report.html.j2
generate_reports() → _collect() output
_collect() reads targets/findings/assets/secret_matches, groups findings by severity; Jinja2 renders the HTML (CVSS/impact added from template lookups). A reports row is written and the file path returned. CLI prints it; the UI serves it at /report/<run_id>.
reads → targets · findings · assets · secret_matches  |  writes → reports + report-*.html
